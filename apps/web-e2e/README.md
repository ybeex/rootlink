# RootLink E2E Tests

End-to-end test suite for the RootLink web application, built with [Playwright](https://playwright.dev).

---

## Test structure

```
apps/web-e2e/
├── tests/
│   ├── auth.setup.ts          Global setup: creates test users, saves auth state
│   ├── auth/
│   │   └── auth.spec.ts       Registration, login, logout, forgot password
│   ├── tree/
│   │   └── tree.spec.ts       Dashboard, tree CRUD, settings, share
│   ├── person/
│   │   └── person.spec.ts     Person CRUD, edit, panel, people page
│   ├── media/
│   │   └── media.spec.ts      Upload, gallery, lightbox, GEDCOM panel
│   ├── collaboration/
│   │   └── collaboration.spec.ts  Settings, notifications, search, invite flow, navigation
│   ├── accessibility/
│   │   └── accessibility.spec.ts  ARIA, keyboard nav, focus, contrast
│   ├── performance/
│   │   └── performance.spec.ts    Core Web Vitals, API latency, asset size
│   ├── visual/
│   │   └── visual.spec.ts     Screenshot regression (light/dark, components)
│   └── api.spec.ts            API-level HTTP tests (no browser)
├── page-objects/              Page Object Model classes
│   ├── LoginPage.ts
│   ├── DashboardPage.ts
│   ├── TreePage.ts
│   └── PersonFormPage.ts
├── helpers/
│   └── fixtures.ts            Typed test fixtures, ApiHelper, extended test object
├── scripts/
│   └── seed-e2e.ts            Provisions test users against the live API
├── fixtures/
│   └── auth-state.json        Browser storage state (auto-generated by setup)
├── playwright.config.ts
├── tsconfig.json
└── .env.test.example
```

## Quick start

### 1. Start services

```bash
# From monorepo root
docker compose up -d postgres redis minio minio_setup
npm run dev
```

### 2. Configure environment

```bash
cd apps/web-e2e
cp .env.test.example .env.test
# Default values work for local dev — no changes needed
```

### 3. Install Playwright browsers

```bash
# From apps/web-e2e
npm run install-browsers
# Or just Chromium for faster install:
npx playwright install chromium
```

### 4. Seed test users

```bash
npm run seed
```

This creates two accounts in your local database:
- `e2e@rootlink.test` / `E2ePassword123!` (primary test user)
- `e2e-collaborator@rootlink.test` / `E2ePassword123!` (collaboration tests)

### 5. Run tests

```bash
# All tests (headless)
npm test

# With browser visible
npm run test:headed

# Interactive UI mode
npm run test:ui

# Smoke tests only (fastest subset)
npm run test:smoke

# Specific suites
npm run test:auth
npm run test:tree
npm run test:person
npm run test:media

# API-level tests only (no browser)
npx playwright test tests/api.spec.ts

# Accessibility audit
npm run test:accessibility

# Performance benchmarks
npm run test:performance

# Visual regression
npm run test:visual
```

### 6. Update visual snapshots

After an intentional design change:

```bash
npm run update-snapshots
# Review the diff, then commit the new .png files
git add tests/visual/snapshots/
git commit -m "chore(e2e): update visual snapshots after redesign"
```

## Writing tests

### Use the extended `test` object from fixtures

```typescript
// Always import from fixtures, not @playwright/test directly
import { test, expect } from '../helpers/fixtures.ts';

test('my test', async ({ page, api, testTree }) => {
  // page     — browser page (pre-authenticated via storageState)
  // api      — ApiHelper for direct HTTP calls (logged in, no browser)
  // testTree — a fresh tree created for this test, deleted after
});
```

### Use Page Objects

```typescript
import { TreePage } from '../page-objects/TreePage.ts';

test('tree toolbar visible', async ({ page, testTree }) => {
  const treePage = new TreePage(page);
  await treePage.goto(testTree.id);
  await treePage.expectLoaded();
  await expect(treePage.addPersonButton).toBeVisible();
});
```

### Tag smoke tests

Mark tests that should run in every CI push with `@smoke`:

```typescript
test('@smoke critical path works', async ({ page }) => {
  // ...
});
```

Run only smoke tests: `npm run test:smoke`

### Clean up after tests

The `testTree` fixture auto-deletes after each test. For persons and other resources created directly:

```typescript
test('my test', async ({ testTree, api }) => {
  const person = await api.createPerson(testTree.id, { firstName: 'Ada', lastName: 'L' });
  // ... test ...
  await api.deletePerson(testTree.id, person.id); // explicit cleanup
});
```

```bash
npx playwright test --grep @smoke
```

## Debugging a failing test

```bash
# Debug mode — pauses on failure, opens Playwright Inspector
npm run test:debug

# Run a single test file
npx playwright test tests/auth/auth.spec.ts

# Run a single test by name
npx playwright test --grep "successful login redirects to dashboard"

# Show the trace viewer for a failed test
npx playwright show-trace test-results/path-to-trace.zip

# Open the HTML report
npm run report
```

### Common failures

| Symptom | Likely cause | Fix |
|---------|-------------|-----|
| `auth-state.json` is empty | Setup project hasn't run | Run `npx playwright test --project=setup` |
| `API not available` | API server isn't running | Run `npm run dev` from monorepo root |
| Visual test fails with diff | Design changed intentionally | Run `npm run update-snapshots` |
| Timeout on `waitForURL('/dashboard')` | Login failed | Check `E2E_USER_EMAIL` and `E2E_USER_PASSWORD` in `.env.test` |
| `WebSocket connection failed` | WS server not available in test env | Expected in unit test runs — WS tests are gated by `enabled` flag |

## CI integration

E2E tests run automatically on every push to `main` and `develop` after unit tests pass.

The CI job:
1. Starts Postgres, Redis, and MinIO as service containers
2. Builds and starts the API and web servers
3. Seeds the E2E test users
4. Runs the full smoke suite with `--project=chromium`
5. Uploads the Playwright HTML report as a build artifact
6. Uploads screenshots on failure for diagnosis

To run E2E tests locally in the same mode as CI:

```bash
npm run test:ci
```

## Snapshots

Visual regression screenshots are stored in `tests/visual/snapshots/` and committed to the repository. The first time you run `npm run test:visual` on a new machine, the tests will **fail** because no baseline exists. Run `npm run update-snapshots` to generate the initial set, review the PNGs, and commit them.

Snapshots are matched with a 2% pixel threshold to tolerate minor antialiasing differences across operating systems.
